# S7-200 SMART 示例工程模板 —— 双工位自动上料·加工·出料站

用 `smart200` MCP 从**空白模板**从零生成、并经四关验证的完整示例工程。
目的：把 S7-200 SMART 常用指令尽量铺开，做成一份可直接抄改的工程骨架。

## 交付物

| 文件 | 说明 |
|---|---|
| `DemoStation.smartV3` | 生成好的工程（V3 格式，MicroWIN SMART V3.2 直接打开） |
| `src/*.awl` | 17 个程序块源码（UTF-8，人读/改这一份） |
| `gbk/*.awl` | 同上转 GBK+CRLF —— **导入软件必须用这一份** |
| `roundtrip.awl` | 从成品工程导出的往返核对件 |

## 规模

**18 个块 / 231 个网络 / 635 条指令 / 158 种指令助记符**

## 块结构

| 块 | 名称 | 网络 | 内容 |
|---|---|---:|---|
| OB1 | `MAIN` | 15 | 调度全部子程序、心跳、运行指示 |
| INT0 | `INT_0` | 3 | 急停中断（事件 0 = I0.0 上升沿），立即封锁输出 |
| INT1 | `INT_1` | 7 | 定时中断 0（100ms）：采样滑动平均、`CRETI` 条件返回、**`PID` 回路运算** |
| INT2 | `INT_2` | 3 | 高速计数中断（事件 12 = HSC0 CV=PV） |
| INT3 | `INT_3` | 3 | 自由口接收完成中断（事件 23） |
| SBR0 | `系统初始化` | 12 | 工艺参数、量程、顺控步复位、`ATCH`/`ENI` |
| SBR1 | `输入信号处理` | 15 | 位逻辑全集：`LD/A/O/AN/ON/NOT`、`EU/ED`、`ALD/OLD`、`LPS/LRD/LPP`、`S/R`、立即指令 `LDI/AI/=I/SI/RI` |
| SBR2 | `定时与计数` | 12 | `TON/TOF/TONR`（1ms/10ms/100ms 三种基准）、`CTU/CTD/CTUD` |
| SBR3 | `顺控主流程` | 41 | **SCR 顺序控制 7 步**：`LSCR`/`SCRT`/`SCRE` |
| SBR4 | `手动操作` | 6 | 点动与互锁 |
| SBR5 | `模拟量处理` | 15 | 标定、限幅、`SQRT/LN/EXP/SIN/COS/TAN`、`ROUND/TRUNC`、偏差 |
| SBR6 | `数学与逻辑` | 13 | 整数/双整数/实数四则、`MUL/DIV`、`INC*/DEC*`、字节/字/双字逻辑、移位与循环移位、`SHRB` |
| SBR7 | `数据处理` | 21 | `MOV*`、块传送 `BM*`、`SWAP/FILL`、表 `ATT/FIFO/LIFO/FND=`、码制转换、`SEG`、`BIR/BIW`、转 ASCII `ITA/DTA/RTA`、`DECO/ENCO` |
| SBR8 | `报警与诊断` | 23 | 比较指令全集、`JMP/LBL`、`FOR/NEXT`、`CRET`、`WDR`、`STOP` |
| SBR9 | `通信处理` | 13 | 自由口 `XMT/RCV`、以太网 S7 `GET/PUT`、站地址 `GPA/SPA` |
| SBR10 | `高速与脉冲` | 11 | `HDEF/HSC`、`PLS`（PTO/PWM）、SM 控制字节 |
| SBR11 | `时钟与统计` | 11 | `TODR/TODW`、扩展时钟 `TODRX/TODWX`、运行小时计、班次产量 |
| SBR12 | `字符串处理` | 7 | `SLEN/SCPY/SCAT/SSCPY/SFND/CFND` 报文与提示文本拼装 |

## 硬件

CPU **ST32**（沿用空白模板的型号，`smart_ui_project_tree` 实读）。
程序用到 `I0.0`~`I1.7` 与 `Q0.0`~`Q1.7`，这 30 个点写符号表时**逐点成功**
（`smart_set_symbols` 对 CPU 上不存在的地址会如实报 `ok=False`，这里全是 `true`），
说明它们在该 CPU 的 I/O 变量表里都有对应行。
换别的 CPU 或接扩展模块时，仍请按实际硬件核对点数与模拟量通道号。

```
I0.0 急停_常闭      I1.0 气缸伸出到位    Q0.0 PTO脉冲输出    Q1.0 安全链输出
I0.1 启动按钮       I1.1 气缸缩回到位    Q0.1 PTO方向输出    Q1.1 蜂鸣器
I0.2 停止按钮       I1.2 工件检测光电    Q0.2 上料电机       Q1.2 就绪指示
I0.3 自动手动切换   I1.3 安全门关闭      Q0.3 加工主轴       Q1.3 手动模式指示
I0.4 复位按钮       I1.4 手动上料        Q0.4 出料电机       Q1.4 完成指示
I0.5 上料到位       I1.5 手动加工        Q0.5 夹紧气缸       Q1.7 心跳输出
I0.6 加工到位       I1.6 手动出料        Q0.6 运行指示
I0.7 出料到位       I1.7 报警确认        Q0.7 报警指示
```
模拟量：`AIW16` 主检测、`AIW18` 备用、`AQW16` 调节输出。

程序里统一写**绝对地址**，符号表只做命名（打开软件会自动显示符号）。
这样即使符号表出问题，也不会让网络变成无效程序段。

## 怎么重建 / 怎么改

改 `src/*.awl` → 转 GBK+CRLF 到 `gbk/` → 一条 `smart_deploy` 搞定
（它会自动把 OB1 排最前、按正确顺序设符号，并跑完五关）：

```
smart_deploy(
    awl_files=[<gbk 目录下全部 .awl，按文件名排序即可>],
    project_path=r"...\DemoStation.smartV3",
    symbols={"启动按钮": "I0.1", ...},
)
```

转码（Git Bash）：
```bash
for f in src/*.awl; do
  iconv -f UTF-8 -t GBK "$f" | sed 's/$/\r/' > "gbk/$(basename $f)"
done
```

## 这份工程踩过、也验过的几条硬规矩

1. **符号表必须在导入程序之前设**，顺序是 `SYMSET…` → `GVTCOMPILE` → `IMPORTPOU…` → `COMPILE`。
   反过来（先有程序再改符号表）编译会报 `-1610612428` 交叉引用错。
2. **落盘只能 `SAVEAS`**。对 `.smartV3` 工程发 `SAVE`，内容会被写进同名的
   `.smart`（V2 格式）文件里，原 `.smartV3` 纹丝不动 —— 按原名再打开看到的是空模板。
3. **`CALL` / `ATCH` 的目标块不存在时，不报编译错，而是让整个网络变成无效程序段。**
   全部块导入完毕后无效标记会自动消失（`POU_IsValidNet` 是动态判定的）。
4. **主程序 OB1 必须最先导入** —— 导入 OB1 会替换整个程序集。
5. **S7-200 SMART 没有 `NETR`/`NETW`**（那是 S7-200 的 PPI 指令），
   以太网 S7 通信用 `GET`/`PUT`。写错的助记符会被当成未定义符号 → 整段无效。
   反过来，`GPA/SPA`、`ITA/DTA/RTA`、字符串六件套、`DECO/ENCO`、`BIW`、`FND=`、
   `TODRX/TODWX`、`PID` 都是**支持**的（`examples/instruction_probe/` 有实测记录）。
   别凭印象回避指令 —— 问软件本人只要一次注入。
6. **一个 Network 只能一条独立逻辑行**；`LSCR` / `SCRE` / `NEXT` / `LBL` 单独成段是合法的。

## 验收记录（2026-08-25）

| 关 | 判据 | 结果 |
|---|---|---|
| 1 静态预检 | `stlcheck` 网络结构 | 17 块 0 无效 |
| 2 编译 | 引擎 `COMPILE` | `ret=0` |
| 3 权威判据 | `POU_IsValidNet`（软件本人）| 17 块 **全部 invalid=0** |
| 4 往返导出 | 重载工程导出后逐块比对 | 块名·网络数·指令流**完全一致** |
| 5 落盘校验 | 工程文件指纹前后比对 | `18511B` → `58160B`，确实写进磁盘 |
| 附 符号存在性 | 导入用符号名的探针块 | 网络有效 → 符号确实落盘 |

第 3、4 关都是**重新载入保存后的文件**做的，不是拿同一个内存实例自证；
第 5 关比对的是磁盘上的文件指纹，独立于软件自报的 `ret=0`。
