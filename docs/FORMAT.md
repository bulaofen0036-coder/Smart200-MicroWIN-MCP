# S7-200 SMART 工程文件格式（逆向记录）

逆向对象：STEP 7-Micro/WIN SMART V3.2（本机 `D:\smart200\`）与 11 个真实 V2 工程。
日期：2026-08-20。所有结论均在多个真实工程上验证过，验证方式写在每节末尾。

## 一、先说结论：这软件没有 Openness 等价物

逐条实测，不是推测：

| 探查项 | 结果 |
|---|---|
| COM / TypeLib 注册 | 无。注册表零命中，博途 `Siemens.Engineering` 那套无法照搬 |
| 主程序命令行参数 | 无有效开关 |
| 内置 JSON-RPC（`JsonRpcClient.dll`） | 只服务 PROFINET 规划器 `MWPNRunner.exe`，符号全是 `PnPort*`/`PnDevicePort*`，不碰程序块 |
| 内置 AI 助手（`MWAIClient.dll`） | 连西门子云 `dida-server.siemens.com.cn/v1/external_chat/qa` + OneID 登录（回调 `127.0.0.1:9123`）。只能聊天，不能操作工程 |
| `Xsd/` 目录 | 全是 GSDML 设备描述模式，与程序无关 |

自动化抓手只有三条：工程文件本身、`.awl` 文本导入导出、UI 自动化。

## 二、容器格式

从资源 DLL `res804.dll` 提取到的文件过滤器（即软件支持的导入导出格式）：

```
(*.awl)|*.awl              POU 程序导出/导入（STL 文本）
(*.sym) (*.csv) (*.txt)    符号表
(*.smartV3;*.smart)        工程（★V3.2 的打开对话框已同时接受 V2 的 *.smart）
(*.smartlibV3;*.mwl)       指令库
(*.td1/*.td2/*.td4)        文本显示器
(*.bin) (*.upd)            固件
```

### V2 `.smart` —— zlib 压缩，可离线解析 ✅

```
偏移 0x00   4 字节   魔数 "SH3\0"
偏移 0x04  16 字节   ASCII 版本串，如 "R02.03.00.00"
偏移 0x70   ...      zlib 流（标准 zlib 头 0x78）
```

解压后为结构化数据，熵约 1.68。

验证：11 个真实现场工程（天车项目 9 个 + RFID 例程 + 一个整机程序），**11/11 解包成功**。
内部版本见过 `V02.03.00.02`、`V02.04.00.00`、`V02.07.00.00`。

### V3 `.smartV3` —— 加密，离线不可解 ❌

```
偏移 0x00   4 字节   0x00000000（无魔数）
偏移 0x04  16 字节   ASCII 版本串 "R03.01.00.00"
偏移 0x100  ...      加密数据
```

判定依据：数据段熵 **7.990 bits/byte**（≈理论上限 8.0），全文件扫描无 zlib / gzip /
zstd / lz4 / bz2 / xz / PK 任何压缩魔数，无任何明文片段。

→ V3 工程只能走 UI 自动化导出 `.awl`。

## 三、解压后的内部结构

### 字符串编码：u16 长度前缀 + GBK

```
[u16 长度][GBK 字节...]
```

**注意：容器内混用两种字节序**，这是踩过的坑 ——
低地址的工程数据段用 big-endian，高地址的系统符号资源段用 little-endian。
最初按单一 BE 假设做验证，68/76 不符；细看不符值 `0x0D00`/`0x0900`/`0x0800`
全是长度左移 8 位，才发现是另一个字节序。

解析器两种都试，并校验解出的内容必须是可打印 ASCII 或合法 GBK 中文。

信噪比实测：真实工程提取 507 条，同长度随机字节只提出 9 条 —— **56 倍**。

### 用户内容 vs 西门子系统内置内容

容器末尾固定挂着西门子的系统符号表（SM 位符号及其中文说明，各工程稳定约 506 条）。
不切掉的话，`初始化`（用户写的）会和`仅在第一个扫描周期时接通`（西门子内置）混在一起。

**切分锚点**：段标题字符串 `系统符号` 的偏移，之前算用户内容。
验证：9/9 个工程锚点均命中，锚点后条数稳定在 506–738 条。

字节序**不能**用来切分（曾误以为可以）——用户注释和系统说明都可能是 LE，已证伪。

### 功能框助记符

`MOV_DW` / `MUL_DI` / `WAND_W` / `ADD_DI` 等以明文出现，但**不带长度前缀**
（前面是 `03 00` 类的类型码），所以长度前缀扫描会把 `MOV_DW` 截成 `MOV`。
单独用正则 `[A-Z][A-Z0-9]{1,9}_[A-Z0-9]{1,8}` 从原始字节匹配，不依赖任何硬编码指令表。

偏移间隔高度规律（如 `0x9cca → 0xa299 → 0xa868`，步长恒定 `0x5cf`），
说明网络是定长记录数组 —— 但**记录内部字段布局尚未逆向完成**。

### 尚未拿下的部分（如实标注，别当成已完成）

- **逐网络 LAD/STL 逻辑还原**：定长记录的字段含义未解，强行输出等于编造。
- **当前 CPU 型号**：工程里存的是模块 ID 而非型号串。实测某现场工程离线搜不到
  `ST32`，只搜到硬件目录条目 `CPU ST20`，而真值是 ST32（UIA 读出）。
  → 不提供离线 CPU 字段，改由 `smart_ui_project_tree` 读。
- **项目名 ≠ 文件名**：容器存的是工程内部名。实测有工程的内部名与文件名完全不同。
  两者都对，是工程另存改名后内部名没同步 —— 不要当成解析 bug 去"修"。

## 四、UI 自动化（V3.2 实测）

- 主窗口 class = **`SmartApp`**（MFC）
- **无传统菜单栏**（`GetMenu` 返回 0），V3 用 Ribbon → 必须走 UIAutomation，
  win32 backend 的菜单命令 ID 那套用不上
- 可读到：项目树（CPU 型号、POU 及其 `OB1`/`SBR16`/`FB0` 编号）、
  `Button:编译`、`Button:打开...`、`Button:保存`、`MenuItem:上传`/`下载`
- 依赖界面语言为简体中文，换语言/换版本控件名会变

**交叉验证**：UIA 项目树读出的 POU 名与离线解析结果 **4/4 完全一致**
（初始化 SBR0 / 并行查询读地址 SBR16 / 地址判定 SBR17 / 中址锁存 SBR18）。
这条互验是离线解析器可信度的主要依据。

## 五、在线通讯

S7-200 SMART 走标准 S7 协议（TCP 102，rack=0 slot=1），**V 区映射为 DB1**。
snap7 可用。⚠ 本项目的在线层**未经真机验证**（开发时无 CPU 可接）。
